# 3+10 감정 분석 프론트 계약

이 문서는 후속 모델 연결을 위한 프론트 입력 계약입니다. 현재 서버의 6종 `POST /api/analyze` 응답은 이 계약을 충족하지 않으며 이번 변경은 네트워크 요청을 추가하지 않습니다.

## 식별자와 의미

분류 버전은 `emotion-cardex-3plus10-v1`입니다. 순서는 `core.js`의 TYPES를 기준으로 합니다. 모델의 출력 벡터 위치를 프론트 ID 순서로 가정하지 말고 체크포인트의 라벨 메타데이터를 통해 매핑해야 합니다.

| 대분류 | 소분류 ID와 명칭 |
|---|---|
| positive | pos_1 기쁨·활력, pos_2 만족·감사, pos_3 안정·자신감 |
| negative | neg_1 불안, neg_2 슬픔, neg_3 분노 |
| neutral | neu_1 객관적 서술, neu_2 의문, neu_3 놀람, neu_4 당황 |

## 기록 분석 객체

```json
{
  "status": "valid",
  "version": 1,
  "taxonomy_version": "emotion-cardex-3plus10-v1",
  "truncated": false,
  "probabilities": {
    "pos_1": 0.1, "pos_2": 0.1, "pos_3": 0.1,
    "neg_1": 0.1, "neg_2": 0.1, "neg_3": 0.1,
    "neu_1": 0.1, "neu_2": 0.1, "neu_3": 0.1, "neu_4": 0.1
  }
}
```

응답은 기록 ID로 대상 기록에 연결하고 `version`은 분석에 사용한 원문 버전과 일치해야 합니다. 원문이 바뀐 결과는 대기로 취급합니다. 분류 버전이 없거나 다르고, 잘렸거나, 확률이 유효하지 않은 결과는 카드에서 실패로 표시하고 통계·수집에서 제외합니다. 원문은 그대로 보관합니다.

확률은 전체 10종을 포함하는 0~1 유한 숫자이며 합계 허용 오차는 1e-6입니다. 구형 6종·7종 결과의 임의 재매핑, 누락 확률의 0 채움, 조건부 자식 확률만으로 전체 분포를 구성하는 것은 허용하지 않습니다. 후속 어댑터는 모델 출력 의미를 확인하고 전체 소분류 확률을 제공해야 합니다.

현재 프론트는 기록 한 편의 확률을 받습니다. 문장별 모델 결과를 기록 단위로 결합하는 정책, 입력 길이 처리, 서버 오류·재시도와 분석 결과 영구 저장은 실제 API 연동 작업에서 확정해야 합니다.

## 표시와 집계

- 카드: 전체 소분류 최다 확률로 결정합니다. 대분류 배지는 그 소분류의 소속입니다. 동률은 TYPES 순서로 고르고 공동 최다를 표시합니다.
- 대분류 통계: 소속 소분류 확률을 합산합니다. 월간 통계는 유효한 기록 각각을 같은 가중치로 평균 냅니다. 날짜별 평균을 다시 평균 내지 않습니다.
- 빈 카드: 최다 확률 30% 미만입니다. 유효한 분석이므로 통계에는 포함하지만 도감을 해제하지 않습니다.
- 카드 단계: 30% 이상~60% 미만은 1단계, 60% 이상~90% 미만은 2단계, 90% 이상은 3단계입니다. 반올림 전에 판정합니다.
- 분류 확률은 감정 강도·심리 점수·모델의 검증 정확도가 아닙니다. 단계 경계는 기존 제품 정책이며 새 모델 연동 시 발급 비율을 평가해야 합니다.

## 저장 호환성

실제 기록은 기존 IndexedDB 스키마 1을 유지합니다. 현재 저장 로직은 분석을 대기로 정규화하므로 예시 분석을 저장하거나 구형 분석을 새 체계로 이전하지 않습니다. 기록 본문·날짜·버전·초안·테마 설정은 유지합니다.
