# MOMENT CARD · 추가 디자인 개선 계획

작성일: 2026-11-02. 기준 버전: `hw/emotion-cardex-v3/`. 상태: **명칭 개정 완료 / 아래 디자인 개선은 계획이며 미구현**.

## 1. 이번에 반영한 사항과 유지할 기준

긍정 소분류 `pos_3`의 시연용 표시명을 **안정 → 평온**으로 개정했다. 새 HTML·검색·카드·차트·로컬 사실 설명·문서와 Figma V3 복제 페이지에 적용했다. 7종 명칭은 기쁨·만족·평온 / 불안·슬픔·분노 / 중립이다. 안정성·안정된 ID 같은 일반 기술 용어는 바꾸지 않았다.

감정 ID, 부모, 3·3·1 구조, 전체 기준 확률, 분모, 윈도우, 축, 결측 처리, API 계약과 `taxonomy_version`은 유지한다. 표시명 확정이 학습 라벨 또는 캐릭터 자산 매핑의 확정을 의미하지 않는다. 이번 변경의 근거·검증은 [LABEL_CHANGE.md](LABEL_CHANGE.md)에 있다.

현재 TCG의 크림·네이비·골드, 카드 번호·프레임, 3대분류를 먼저 고르고 소분류로 들어가는 탐색, 라이트·다크·시스템 모드를 유지한다. 원본 Figma와 기존 v1·v2·루트 코드는 보존한다. 후속 디자인 구현도 별도 작업 버전에서 진행한다.

## 4. 영역 배치와 컴포넌트 변경안

### 데스크톱 1440px

좌측 내비게이션과 상단 화자·분석 범위를 유지한다. 본문은 다음 순서로 구성한다.

1. 대표 카드 + 대표 대분류 / 최다 소분류 + 유효 표본·분석 범위
2. 3대분류 분포 + 부모별7소분류 분포, 각 숫자의 기준 설명
3. 발화 흐름 + 변화 구간/관찰 요약
4. 작은 도감 미리보기 + 전체 갤러리 진입
5. 반복 표현과 종합 설명의 상세

대표 카드가 설명과 통계를 밀어내지 않게 크기를 제한한다. 수치·부모 의미 색상·TCG 프레임을 유지하며, 통계가 먼저 읽히도록 골드 장식의 대비와 면적을 조절한다.

### 태블릿 768–1023px

대표 카드/핵심 지표2열, 그래프는 충분한 폭으로 재배치한다. 갤러리2–3열, 상세 이미지는 통계보다 먼저, 긴 표는 우선 열과 상세 펼치기로 구성한다. 태블릿 전용 기능을 추가하지 않는다.

### 모바일 390px, 최소320px

상단 화자·범위 → 핵심 두 대표와 해석 안내 → 3대분류와 하위 통계 → 흐름 요약 → 반복 표현/관찰 요약 → 작은 도감 미리보기 → 상세 설명 순서로 재구성한다. 상세 차트는 전용 화면에서 더 크게 확인한다. 주요 수치·행동에 가로 스크롤을 요구하지 않는다.

전체 갤러리는2열을 유지하고 작은 유형 목록은 Overview에만 사용한다. 하단 내비게이션을 유지하며 safe-area와 44px 터치 목표를 점검한다. 긴 화자·감정 설명·200% 확대는 별도 검사한다.

| 영역 | 제안 컴포넌트 계층 | 핵심 상태·상호작용 |
|---|---|---|
| 결과 요약 | `ResultContext > SummaryMetrics > InterpretationNote` | 유효/없음/불가를 구분, 부모와 자식이 다른 예시 설명 |
| 분류 탐색 | `TaxonomyExplorer > ParentSelector > LeafResults > EmotionCard` | 부모 선택, 검색/정렬, 결과 수, 해제, 상세 복귀 |
| 흐름 | `FlowPanel > SeriesControls > ChartNavigator > PointSummary > DataTable` | 5보기, 계열 선택, 키보드 포인트 탐색, 툴팁·표 |
| 미리보기 | `CardexPreview > RepresentativeCard > CompactTypeList > GalleryLink` | 번호/색/이름/확률, 전체7종 접근 |
| 상세 | `CardDetail > VisualSlot > FactsPanel > LeafTrend > EvidencePanel` | 확대, 이전/다음, 해당 흐름, 돌아가기 |
| 설명 | `InsightSummary > RepeatedExpressions > NarrativeStatus` | 표본 기준, 사실 설명, 독립 재시도 |

컴포넌트 명칭은 역할을 설명하는 계획용 이름이다. 현재 순수 JavaScript 구조를 유지하고 렌더 함수를 작은 단위로 분리할 수 있으며, React 도입은 전제하지 않는다.

## 6. 기술 변경과 데이터 경계

- `scripts/core.js`: 감정 명칭의 단일 원천 유지. 집계·모델 계약 변경은 이번 디자인 작업에서 제외한다.
- `scripts/app.js`: Overview 미리보기/탐색 요약/차트 키보드 렌더를 역할별로 분리한다. `parentId`, `leaf`, 검색, 정렬, 복귀 경로와 초점은 동일 상태를 참조한다.
- `styles/`: 의미 토큰→공통 컴포넌트→반응형·테마 순서로 정리한다. CSS custom properties, 네이티브 버튼·select·dialog와 의미 있는 HTML을 우선한다.
- `templates/shell.html`·`tools/build.mjs`: 분리 소스와 단독 실행 `index.html`의 파생 관계를 유지한다. 기존 루트 파일을 덮어쓰지 않는다.
- Figma: 신규 작업 페이지에서 토큰 모드와 핵심 화면을 수정하고, node ID/HTML 라우트/고정 예시 데이터의 대응표를 갱신한다.
- 현재 저장소의 이전6분류 `/api/analyze`를7개로 임의 변환하지 않는다. 운영3+7 모델·API 연결은 별도 선행 과제다. 이 디자인 개선에는 신규 서버 API가 필요하지 않다.
- 통계·자연어 설명·이미지는 독립 비동기 상태를 유지한다. 설명/이미지 실패가 성공한 통계와 그래프를 초기화하지 않게 한다.

보편적으로 강제되는 단일 웹 폴더 표준이 있다는 전제는 두지 않는다. 현재 MDN의 `index/styles/scripts` 관례를 따른 구조에 필요한 경계를 보완한다. 별도 빌드 프레임워크·상태 라이브러리 도입을 개선 목표로 삼지 않는다.

아래 후속 검증은 **아직 수행하지 않았다**. 명칭 개정 릴리스에서 수행한 결과와 구분한다.

운영 모델 품질·임상 판단·감정 강도 추정은 디자인 테스트의 합격 주장에 포함하지 않는다. Radar Chart를 다시 필수 그래프로 넣지 않는다.

## 9. 보류·미확정 사항

학습 라벨·7자산 매핑, 운영3+7 API, 실제 설명/이미지 서비스, 대화 저장 정책, 희귀도·팩·획득·영구 수집·진화·업적은 별도 결정 사항이다. 승인 자산이 없으므로 이미지 슬롯은 계속 비워 둔다. 다크 Figma, 새 Overview와 차트 키 탐색은 이 문서의 제안이며 이번 명칭 개정에 구현하지 않았다.
